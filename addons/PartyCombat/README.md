# PartyCombat

PartyCombat is a Windower 4 addon for deliberately coordinating physical
combat across multiboxed characters without handing movement to HealBot or
blindly mirroring the leader's selected target.

This initial prototype was generated by OpenAI Codex for a six-character
Valefor party:

- Leader: `Dolomedes`
- Authorized attacker: `Tackleberry`
- Automatic pursuit limit: 10 yalms
- Explicit forced-pursuit limit: 30 yalms

It is intentionally conservative. Loading the addon does nothing until the
leader arms it.

## Behavior

PartyCombat follows combat actions, not cursor movement:

- Merely tabbing to another enemy does not move Tackleberry.
- A resolved melee or ranged attack, weaponskill attempt, or damaging spell
  from Dolomedes announces that enemy as the automatic combat target. A miss
  still counts because Dolomedes deliberately attacked that enemy.
- Automatic target changes are accepted only when the enemy is within
  Tackleberry's configured 10-yalm limit.
- `force` explicitly targets, approaches, and engages Dolomedes' current enemy
  up to the configured 30-yalm safety limit.
- The attacker stops moving at 2.8 yalms.
- A dead, despawned, or invalid target ends the pursuit.
- Zoning disarms the addon.
- Only configured attackers respond. Other characters are observers.

PartyCombat clears inherited FastFollow and HealBot follow/assist/engage state
when it authorizes an attacker. GearSwap remains responsible for equipment,
and AutoWS2 or another separately configured system remains responsible for
weaponskills.

## Installation

Copy the `PartyCombat` directory into `Windower\addons`, then load it on every
local client:

```text
lua load PartyCombat
```

All clients share one Windower settings file. If simultaneous first-time loads
observe that XML while another client is still creating it, PartyCombat falls
back to its safe in-memory defaults instead of aborting. A later reload uses
the completed file.

Recommended `scripts\init.txt` bindings:

```text
bind !p pcombat force
bind !o pcombat stop
```

Windower uses `!` for Alt, so these are Alt+P and Alt+O. Commands are accepted
only when issued from the configured leader.

## Commands

```text
//pc on
//pc force
//pc stop
//pc status
//pc help
```

- `on`: Arms automatic damage-target synchronization without selecting or
  approaching anything.
- `force`: Arms synchronization and explicitly orders the configured attacker
  to approach and engage the leader's current enemy.
- `stop`: Disarms synchronization, stops movement, and disengages attackers.
- `status`: Displays the local client's role, authorization, target, and mode.

The normal flow is:

1. Target the intended enemy on Dolomedes.
2. Press Alt+P once.
3. Continue fighting normally. Tackleberry follows enemies Dolomedes actually
   attacks when they are within the automatic leash.
4. Press Alt+O to stop and revoke combat authorization.

## Configuration

Windower creates `addons\PartyCombat\data\settings.xml`. The default structure
contains one attacker:

```xml
<leader>Dolomedes</leader>
<attackers>
    <Tackleberry>
        <auto_distance>10</auto_distance>
        <force_distance>30</force_distance>
        <engage_distance>2.8</engage_distance>
    </Tackleberry>
</attackers>
```

Additional attackers can be added later as character-named entries. Each
client must use the same configuration.

## PartyStart integration

PartyCombat broadcasts an explicit authorization heartbeat while armed.
PartyStart recognizes that authorization and temporarily exempts the named
attacker from its follower-combat guard. PartyStart continues protecting
Smalls, Barneystinson, Achoo, and every other unapproved follower.

Stopping or zoning revokes authorization.

## Safety and limitations

- This is a live-test prototype. Begin on harmless enemies in an open area.
- Movement is a straight line. It does not path around walls, hazards, or
  additional enemy groups.
- The automatic leash is measured from the attacker to the enemy, not from the
  leader.
- Damaging area-of-effect actions select the first valid enemy reported in the
  action packet.
- Non-damaging enfeebles do not change the automatic combat target.
- Force mode is deliberately capped at 30 yalms; it is not unlimited.
- PartyCombat does not automate weaponskills, rolls, ranged attacks, or
  defensive behavior.
