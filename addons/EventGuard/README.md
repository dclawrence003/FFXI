# EventGuard

EventGuard is an experimental Windower 4 addon for diagnosing and sometimes
recovering an FFXI client that remains locked in an NPC interaction after the
rest of the party has moved on.

It records the most recent NPC menu packet and self-status update while the
client is healthy. Those real values give its recovery commands more context
than blindly injecting a generic reset.

## Important warning

This is a prototype that works with FFXI packets. A client and server can remain
desynchronized even when movement appears to return. Relog if recovery does not
work immediately, if zoning fails, or if behavior remains abnormal.

## Installation

Copy this directory to:

```text
Windower\addons\EventGuard
```

Load it before an interaction becomes stuck:

```text
//lua load EventGuard
```

To keep the recorder active, add this to `Windower\scripts\init.txt`:

```text
lua load EventGuard
```

The addon stores one small per-character event record under its local `data`
directory. That runtime data should not be shared.

## Commands

| Command | Behavior |
| --- | --- |
| `//eg status` | Shows current player status and the recorded menu/recovery state |
| `//eg soft` | Injects the standard local NPC-release sequence |
| `//eg menu` | Sends cancellation for the last recorded menu, but only in the same zone |
| `//eg recover` | Runs the soft release and recorded-menu cancellation |
| `//eg local confirm` | Forces the latest real self-update packet from Event to Idle after explicit confirmation |

`//eg local confirm` is intentionally awkward because it is the highest-risk
option. Use it only after the normal recovery commands fail.

## Design safeguards

- Refuses to cancel a recorded menu from another zone.
- Uses an actual recorded NPC ID, target index, zone, and menu ID.
- Requires the word `confirm` for forced local status recovery.
- Does not automate NPC choices or travel.

## Prototype limitations

- EventGuard cannot prove that the server accepted a local recovery.
- It cannot repair every invalid menu state.
- A relog remains the safest definitive reset.
- Packet structures may change.
