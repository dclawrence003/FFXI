# MultiCtrl Warp II queue patch

This patch iterates on MultiCtrl, whose installed source identifies **Kate** as
the author. A public source tree is available at
[Mary-Elizabeth/FFXI-Addons](https://github.com/Mary-Elizabeth/FFXI-Addons/tree/master/Multictrl).
The full original addon is not redistributed here.

## Problem addressed

The original `//mc d2` loop sent Warp II commands with a short fixed delay. In a
multibox party, an action lock, recast delay, insufficient MP, or slow client
departure could cause one member to be skipped while the loop continued.

## Changes

- Builds a deterministic queue of nearby party members.
- Waits for the caster to become actionable.
- Confirms that Warp II began.
- Waits for the target to leave the nearby party state.
- Retries failed targets a configurable number of times.
- Keeps the caster in place when any recipient fails.
- Adds `status`, `retry`, and `cancel` controls.

Commands:

```text
//mc d2
//mc d2 status
//mc d2 retry
//mc d2 cancel
```

Settings added to MultiCtrl defaults:

```lua
d2_retry_count = 3
d2_post_cast_delay = 2.5
d2_start_timeout = 4.0
d2_success_timeout = 18.0
```

## Compatibility warning

This patch was generated from an already customized local MultiCtrl file. Its
pre-patch file does not exactly match the current public source tree, so
`git apply` may require manual conflict resolution. Review the patch before
using it.

## Apply

Back up `multictrl.lua`, place the patch beside the customized source tree, and
first perform a dry check:

```powershell
git apply --check C:\path\to\warp-ii-queue.patch
```

Only apply it if the check succeeds:

```powershell
git apply C:\path\to\warp-ii-queue.patch
```

## SalvageCells lifecycle compatibility

`salvagecells-persistent-load.patch` removes MultiCtrl's delayed Remnants-zone
load and exit unload behavior for SalvageCells. SalvageCells must instead load
from Windower `init.txt` before entering Remnants so all clients observe the
same zone-entry event and retain coordinator state for the full run.

## Action-event CPU hot path

`action-event-hot-path.patch` removes MultiCtrl's second parse of every nearby
`0x028` action packet. The existing Windower `action` event already supplies
the decoded action, so MultiCtrl now uses that object for its casting and Warp
II queue state. It filters by the local player before changing either state,
which also prevents another actor's cast from toggling this client's
`isCasting` flag.
